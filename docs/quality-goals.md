# Quality goals

These are WarnWeather's quality goals where it differs from an ordinary app. Each row names the check that guards it.
When a change trips a check, fix the change and leave the check as it is.

| Top Level Dimension | Short Description | Expected Values | Measure | Acceptance Criteria |
| --- | --- | --- | --- | --- |
| Performance efficiency (memory) | Pebble Classic and Steel (aplite) load the whole app image into 24 KB of RAM and need about 2.5 KB left to start it. Past that the watchface silently never launches. | Aplite image (text + data + bss) at or under the ceiling in `scripts/check-aplite-size.sh`; peak free heap about 1.5 KB at runtime. | `scripts/check-aplite-size.sh` (`mise check-aplite-size`), runtime heap logs on the diorite proxy (`MEMORY_LOG_HEAP`). | The check passes on every change that touches C; a change that grows the aplite image is reviewed for bytes it can reclaim. |
| Performance efficiency (memory) | basalt, diorite and flint have 64 KB app images with little room left. | Each image at or under its recorded ceiling. | `scripts/check-64k-size.sh` (`mise check-64k-size`). | The check passes; a ceiling is only lowered, or raised against a measured runtime low point. |
| Compatibility (wire) | Phone and watch talk over a half-duplex AppMessage channel whose inbox is fixed per platform (`src/c/appendix/app_message.c`). An oversized message is dropped without an error. | The heaviest weather and settings bundles fit every platform's inbox with at least 10 B to spare. | `test/repo/inbox-size.test.js` computes each heaviest bundle per platform. | The test passes; a payload change updates its heaviest bundle in the same commit. |
| Compatibility (runtime) | The phone app runs on aplite's pre-ES2015 JavaScriptCore, and the settings page in old Android webviews. ES2015 syntax breaks the whole bundle; an ES2015 built-in throws when its line runs. | Every file under `src/pkjs` parses as ES5 and calls only ES5 built-ins or polyfilled ones; the ES5 test skips `*.generated.js`, `dev-config.js` and test folders, so their generators and authors keep those ES5. | `test/repo/config-es5.test.js`, `test/repo/polyfills.test.js`, `test/repo/config-page-polyfills.test.js`. | The tests pass. |
| Compatibility (upgrade) | Users keep their settings and on-watch data across every update. | Stored settings and persist keys from any released version upgrade without loss. | Append-only persist keys (`src/c/appendix/persist.h`), settings migrations and their tests (`test/settings/application/clay-migrations.test.js`, `test/settings/adapter/migration-screens.test.js`), the schema golden file (`test/config-schema.golden.json`). | Migration tests pass; no persist key is reordered or removed. |
| Performance efficiency (battery) | The watch runs for days on a small battery. | No second ticks (minute and day ticks only); no redraw or flash write when nothing changed. | The tick subscription in `src/c/windows/main_window.c` (minute and day units), `test/architecture/c-includes.test.js` (no `SECOND_UNIT` anywhere), the persist helpers that compare before writing, the phone's change detector (`src/pkjs/wire/adapter/change-detector.js`). | The tests pass. |
| Security (privacy) | Positions, keys and tokens never land in server logs or URLs the app controls. | Coordinates rounded to 3 decimals before they leave the phone for Rainbow; edge functions log a fixed tag plus at most a machine code. | `test/repo/supabase-log-hygiene.test.js`, `test/weather/domain/coords.test.js`, the edge functions' Deno tests. | The tests pass. |
| Security (permissions) | The Pebble app lets the phone app reach only the hosts it declares. | Every host the app requests is declared with a reason; nothing declared goes unused. | `test/repo/uses-permissions.test.js`. | The test passes. |
| Maintainability (aplite) | Aplite is a frozen, lean fork (ADR 0001): its twins get bug fixes but no features. | Every `foo_aplite.c` has its `foo.c` and `foo.h`; a change to a base file is reviewed against its twin. | `scripts/check-aplite-twins.js` (CI workflow `aplite-twins-required.yml`), `test/watchface/aplite-twins.test.js`. | CI passes. |
| Reliability (lower than usual) | Telemetry and news are best-effort; a missed upload or an unavailable edge function never affects the watchface. | Telemetry keeps a small queue with backoff and drops stale events; no uptime target for the edge functions. | The edge functions' Deno tests; `test/telemetry/adapter/telemetry.test.js`, `test/notices/adapter/news-cache.test.js`. | The watchface works with every edge function down. |
