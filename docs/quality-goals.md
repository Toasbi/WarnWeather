# Quality goals

The goals where WarnWeather differs from an ordinary app. Each names the check that guards it;
a change that trips one fixes the change, not the check.

| Top Level Dimension | Short Description | Expected Values | Measure | Acceptance Criteria |
| --- | --- | --- | --- | --- |
| Performance efficiency (memory) | Pebble Classic and Steel (aplite) load the whole app image into 24 KB of RAM and need about 2.5 KB left to start it at all. Past that the watchface silently never launches. | Aplite image (text + data + bss) at or under 21804 B; peak free heap about 1.5 KB at runtime. | `scripts/check-aplite-size.sh` (`mise check-aplite-size`), runtime heap logs on the diorite proxy (`MEMORY_LOG_HEAP`). | The check passes on every change that touches C; no change makes the aplite image larger without bytes reclaimed elsewhere. |
| Performance efficiency (memory) | basalt, diorite and flint have 64 KB app images with little room left. | Each image at or under its recorded ceiling. | `scripts/check-64k-size.sh` (`mise check-64k-size`). | The check passes; a ceiling is only lowered, or raised against a measured runtime low point. |
| Compatibility (wire) | Phone and watch talk over a half-duplex AppMessage channel whose inbox is fixed per platform: 536 B on aplite, 640 B on most watches, 1280 B on emery. An oversized message is dropped without an error. | The heaviest weather and settings bundles fit every platform's inbox with at least 10 B to spare. | `test/inbox-size.test.js` computes each heaviest bundle per platform. | The test passes; a payload change updates its heaviest bundle in the same commit. |
| Compatibility (runtime) | The phone app runs on aplite's pre-ES2015 JavaScriptCore, and the settings page in old Android webviews. ES2015 syntax kills the whole bundle; an ES2015 built-in throws when its line runs. | Every file under `src/pkjs` parses as ES5 and calls only ES5 built-ins or polyfilled ones; the ES5 test skips `*.generated.js`, `dev-config.js` and test folders, so their generators and authors keep them ES5. | `test/config-es5.test.js`, `test/polyfills.test.js`, `test/config-page-polyfills.test.js`. | The tests pass. |
| Compatibility (upgrade) | Users keep their settings and on-watch data across every update. | Stored settings and persist keys from any released version upgrade without loss. | Append-only persist keys (`src/c/appendix/persist.h`), settings migrations and their tests (`test/clay-migrations.test.js`, `test/migration-screens.test.js`), the schema golden file (`test/config-schema.golden.json`). | Migration tests pass; no persist key is reordered or removed. |
| Performance efficiency (battery) | The watch runs for days on a small battery. | Minute ticks only (day ticks where the calendar needs them); no redraw or flash write when nothing changed. | `tick_timer_service_subscribe` in `src/c/windows/main_window.c`, the persist helpers that compare before writing, the phone's change detector (`src/pkjs/change-detector.js`). | No second ticks; the change-detector tests pass. |
| Security (privacy) | Positions, keys and tokens never land in server logs or URLs the app controls. | Coordinates rounded to 3 decimals before they leave the phone for Rainbow; edge functions log a fixed tag plus at most a machine code. | `test/supabase-log-hygiene.test.js`, `test/coords.test.js`, the edge functions' Deno tests. | The tests pass. |
| Security (permissions) | The Pebble app lets the phone app reach only the hosts it declares. | Every host the app requests is declared with a reason; nothing declared goes unused. | `test/uses-permissions.test.js`. | The test passes. |
| Maintainability (aplite) | Aplite is a frozen, lean fork (ADR 0001): its twins get bug fixes but no features. | Every `foo_aplite.c` has its `foo.c` and `foo.h`; a change to a base file is reviewed against its twin. | `scripts/check-aplite-twins.js` (CI workflow `aplite-twins-required.yml`), `test/aplite-twins.test.js`. | CI passes. |
| Reliability (lower than usual) | Telemetry and news are best-effort; a missed upload or an unavailable edge function never affects the watchface. | Telemetry keeps a small queue with backoff and drops stale events; no uptime target for the edge functions. | The edge functions' Deno tests; `test/telemetry.test.js`, `test/news-cache.test.js`. | The watchface works with every edge function down. |
